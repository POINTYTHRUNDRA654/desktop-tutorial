# Collision & Physics for Custom Meshes — Fallout 4 (2026)

This guide covers the full Havok collision authoring pipeline for custom NIF meshes: shape types, MOPP generation, filter layers, vegetation-specific physics flags, and the NifSkope/HKX workflow.

---

## 1. Why Custom Collision Matters

Every object placed in the game world needs collision geometry for:
- **Player/NPC physical interaction** — standing on, bumping into
- **Projectile and explosion hit detection** — bullets, grenades, AoE
- **Ragdoll physics** — NPC bodies landing on/against objects
- **Havok world query** — used by AI pathfinding, scripts (`bhkPickData` raycasting)

Without correct collision, characters pass through meshes, AI gets confused, and physics objects clip.

## 2. Havok Shape Types

Fallout 4 uses Havok 2014 physics. NIF collision nodes reference Havok shape types:

| Shape type | NIF class | Use case | Cost |
|---|---|---|---|
| **Box** | `bhkBoxShape` | Rectangular crates, walls, simple props | Very cheap |
| **Sphere** | `bhkSphereShape` | Balls, round fruits | Very cheap |
| **Capsule** | `bhkCapsuleShape` | Pillars, barrels, character cylinders | Cheap |
| **Convex Hull** | `bhkConvexVerticesShape` | Irregular-shaped props (rocks, tools) | Moderate |
| **Compressed Mesh** | `bhkCompressedMeshShape` + `bhkCompressedMeshShapeData` (MOPP) | Terrain, complex static meshes | Expensive (static) |
| **List** | `bhkListShape` | Composite of multiple shapes | Sum of children |
| **Transform** | `bhkTransformShape` | Offsets a child shape | Negligible overhead |

### Choosing the Right Shape

**Rule of thumb — use the simplest shape that approximates the mesh:**

| Object type | Recommended shape |
|---|---|
| Box/crate | `bhkBoxShape` |
| Round barrel | `bhkCapsuleShape` |
| Irregular rock/debris | `bhkConvexVerticesShape` |
| Terrain / ground | `bhkCompressedMeshShape` (MOPP) |
| Building wall | `bhkBoxShape` or multiple boxes |
| Tree trunk | `bhkCapsuleShape` (vertical) |
| Vine / hanging plant | No physics collision — use trigger volume only |
| Custom large flora | `bhkConvexVerticesShape` for canopy, capsule for trunk |

## 3. bhkConvexVerticesShape — Authoring in Blender

The convex hull is the most commonly used shape for irregular props. A convex hull wraps the minimum convex volume around your mesh.

### Blender Workflow

1. Select your prop mesh
2. Create a new mesh object named `[P]YourPropColMesh` (the `[P]` prefix is recognized by the NIF exporter as a collision proxy)
3. Apply Blender's `Convex Hull` modifier → result is the collision proxy
4. Export to NIF via the Blender NIF plugin
5. In the exported NIF, the proxy mesh becomes a `bhkConvexVerticesShape`

### Key Parameters

| Parameter | Value | Notes |
|---|---|---|
| `bhkRadius` | 0.1–0.01 | The margin around vertices — lower = tighter fit but more penetration artifacts |
| Material | `SKY_HAV_MAT_STONE` or `FOG_HAVOK_MAT_STONE` | Determines physics material for footsteps + impacts |
| Mass | 0 = static; > 0 = dynamic | Use 0 for all placed static objects |

## 4. bhkCompressedMeshShape (MOPP) — Terrain and Complex Statics

MOPP (Memory Optimized Partial Polytope) is a spatial indexing structure that allows fast ray queries against complex triangle meshes.

### When to Use MOPP

- Terrain pieces with concave surfaces
- Cave floors/ceilings
- Custom ground plates with height variation
- Any mesh where a convex hull would miss major cavities

### MOPP Generation Methods

**Method 1: Havok Content Tools (official, Windows)**
1. Export mesh from Blender/3ds Max as `.fbx`
2. Import into Havok Content Tools (standalone app from Havok SDK)
3. Use `Physics > Generate Compressed Mesh Shape`
4. Export as `.hkx`, then convert to NIF via hkxconv or nifskope

**Method 2: NifSkope auto-generate (for existing NIFs)**
1. Open NIF in NifSkope
2. Right-click root BSFadeNode → `Block > Attach Havok > Compress Mesh`
3. NifSkope generates the MOPP data automatically
4. Save NIF

**Method 3: Outfit Studio / BodySlide physics** — not applicable for static collision

### MOPP Performance Budget

| Mesh complexity | MOPP cost | Recommendation |
|---|---|---|
| < 500 triangles | Fast | Fine for all uses |
| 500–5000 triangles | Moderate | Use for key terrain pieces only |
| > 5000 triangles | Slow query | Split into multiple simpler shapes |

Terrain generated by the CK uses MOPP automatically. For custom terrain inserts, keep collision mesh under 2000 triangles.

## 5. Havok Filter Layers (Collision Groups)

Every collision shape belongs to a **layer** that determines what it interacts with. This is set in the `bhkRigidBody.layerCopy` field.

### Key FO4 Havok Layers

| Layer value | Name | Interacts with |
|---|---|---|
| 1 | `STATIC` | Everything — default for static world geometry |
| 2 | `ANIMSTATIC` | Everything — for animated static objects |
| 6 | `DEBRIS_SIMPLE` | Simple physics debris (bottles, cans) |
| 8 | `BIPED` | Player and NPC character capsules |
| 9 | `PROJECTILE` | Bullets, arrows |
| 12 | `TREES` | Tree trunks/canopy — vegetation layer |
| 14 | `PROPS` | Physics props (chairs, barrels) |
| 15 | `WATER` | Water surface volume |
| 17 | `CLOTH` | HDT-SMP cloth/hair |
| 20 | `STATIC_LOD` | LOD collision geometry |
| 35 | `VEGETATION` | Grass and small plant proxy volumes |

### Vegetation-Specific Layer Rules

For custom plants and trees:
| Part | Layer | Reason |
|---|---|---|
| Tree trunk (solid) | `TREES` (12) | Characters can lean against; projectiles hit |
| Canopy / leaves (if any) | `VEGETATION` (35) | Soft hit detection only; doesn't block movement |
| Underground roots | `STATIC` (1) | Solid ground-level obstacle |
| Vines hanging | No collision | Performance — vines are visual only |
| Sentient plant bite hitbox | `BIPED` (8) or custom trigger | For melee attack detection |

## 6. NifSkope Collision Setup

### Hierarchy Structure

```
BSFadeNode (root)
├── BSTriShape "VisualMesh"            ← visible geometry
│   └── BSLightingShaderProperty
└── bhkCollisionObject
    └── bhkRigidBody
        ├── layer = 1 (STATIC)
        ├── motionType = MO_SYS_FIXED  ← for static objects
        └── bhkConvexVerticesShape     ← the actual collision shape
```

### Setting Layer in NifSkope

1. Expand the `bhkCollisionObject` → `bhkRigidBody`
2. In the `Layer` field, enter the numeric layer value (e.g., 12 for TREES)
3. Set `motionType`:
   - `MO_SYS_FIXED` (1) — static, unmovable
   - `MO_SYS_SPHERE_INERTIA` (4) — dynamic physics (bottles, cans)
   - `MO_SYS_BOX_INERTIA` (5) — box-shaped dynamic object
4. Set `mass` in the `bhkMassProperties` node:
   - 0.0 = static (infinite mass)
   - 5.0–50.0 = dynamic objects (books, bottles, small props)

### BSX Flags for Collision

On the root BSFadeNode → BSXFlags, ensure `Havok` flag is set:
```
BSXFlags value: bHavokEnabled = bit 1 = decimal 2
```
Without this flag, the game engine ignores collision even if the collision hierarchy is present.

## 7. Trigger Volumes (Zone Activation)

Trigger volumes are non-solid collision shapes used for zone detection (OnTriggerEnter/OnTriggerLeave events in Papyrus).

### Creating a Trigger Volume

1. In the CK, place an `Activator` with marker flag enabled
2. Attach collision via the NIF: use `bhkBoxShape` or `bhkSphereShape`
3. Set the `bhkRigidBody.layer` to a trigger layer — usually `0` (no collision response) with the `isTrigger` flag set in BSXFlags
4. In Papyrus, reference the activator's `OnTriggerEnter` event:

```papyrus
Event OnTriggerEnter(ObjectReference akRef)
    ; player or NPC entered the trigger zone
    if akRef == Game.GetPlayer()
        ; trigger plant awareness
        PlantScript.SetThreatState(1)
    endIf
endEvent
```

## 8. Physics Performance Guidelines

| Rule | Details |
|---|---|
| Max active dynamic objects | ~200 simultaneous physics objects per cell before performance degrades |
| Static vs dynamic | Every non-essential physics prop should be `MO_SYS_FIXED` (static) |
| Convex hull vertex budget | Keep convex hull shapes under 64 vertices (Havok limit is higher but query is faster with fewer) |
| MOPP triangle budget | Under 2000 triangles per MOPP shape |
| Layer filtering | Use correct layer — incorrect layers cause AI pathfinding failures and projectile pass-through |
| Vegetation collision | Use thin `bhkCapsuleShape` for trunk, no collision for leaves — mass foliage collision destroys FPS |

## 9. Checklist for Custom Mesh Collision

- [ ] BSXFlags → `bHavokEnabled` bit set on root node
- [ ] `bhkCollisionObject` → `bhkRigidBody` present
- [ ] Correct shape type for mesh complexity (box/capsule/convex hull/MOPP)
- [ ] `motionType` = `MO_SYS_FIXED` for static objects
- [ ] `mass` = 0 for static objects
- [ ] Layer set correctly (STATIC=1, TREES=12, VEGETATION=35, PROPS=14)
- [ ] Convex hull vertices < 64 per shape
- [ ] MOPP triangles < 2000 per shape
- [ ] Vegetation: trunk = capsule/convex hull (layer 12), leaves = no collision
- [ ] Trigger volumes: layer 0 + isTrigger flag for Papyrus zone events
- [ ] Dynamic objects: `bhkMassProperties` mass set (5–50 for typical props)
