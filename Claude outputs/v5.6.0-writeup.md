# Mossy FO4 Blender Add-on — v5.3.4

## Multi-Material Fixes

This update fixes a class of bugs where tools in the add-on only ever read or wrote to material slot 0 on an object, ignoring whatever material was actually selected/active. On any mesh with more than one material — armor with cloth + metal + leather pieces, a creature with a separate eye/mouth material, a weapon with a scope and a body material — these tools were silently working on the wrong material, or overwriting a material that had nothing to do with the button you pressed.

If you only ever build single-material objects, this update won't change anything you see. If you work with multi-material meshes, several tools should now behave the way you'd expect instead of quietly clobbering slot 0.

### What's fixed

- **Setup FO4 Materials** — no longer skips (or wrongly reports "already textured") based on slot 0 alone; now checks every material slot on the object.
- **Glow Effects** (Pulsate / Aurora / Breathe / Flicker / Rainbow / Spore) — now applies to the object's actual active material instead of always grabbing slot 0. Fixes glow effects landing on the wrong material on multi-material meshes.
- **Glow Map Sequence Baker** — same active-slot fix, so the baked _g.dds sequence targets the right material.
- **Material Browser presets** (Wet, Metal, Skin, Glow Plant, and the rest) — presets now apply to and read back from the active material slot, instead of a mismatch where the preset applied to one slot but the follow-up read looked at another.
- **Hybrid Unwrap / Rebake Texture to New UV** — UV backup and texture detection now check all material slots instead of assuming the texture lives in slot 0.
- **Wrap Image onto Mesh / Retouch Texture** — material lookup now respects the active slot.
- **NIF drag-and-drop texture import** — dropped textures now attach to the active material.
- **AO Bake** — bakes to the active material's node tree instead of always slot 0.
- **Ambient Occlusion / Core Material Profile presets** (Foliage, Wet, Metal, Skin) — same active-slot fix as the Material Browser.
- **FO4 Scene Diagnostics** — the material health check now reports on every material slot on an object, not just the first one, so multi-material meshes get a complete diagnostic instead of a partial one.
- **Advisor auto-fix ("Setup FO4 Material")** — now evaluates and fixes every material slot on selected objects, not just the first.

### Technical note

The root cause in several of these was `fo4_material_browser.MaterialBrowser.apply_preset()` writing presets to material slot 0 unconditionally. Several operators that call it and then read back `obj.data.materials[0]` were "fixed" downstream without fixing the actual write — this update fixes the source (`apply_preset` now writes to the active slot) so the write and read-back stay in sync everywhere it's used.
