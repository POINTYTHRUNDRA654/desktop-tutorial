## How to Use This Guide

This guide explains the 22 current platform pages in Mossy, what each page is for, and the best way to use it.

Each page section gives you:
- the main purpose of the page
- a simple step-by-step way to use it
- a quick map of the major areas you will see
- practical tips for new users

If you are brand new, read the first-run checklist first, then move through the pages in order.

## Newbie First Run Checklist

1. Open Mossy.Space (Page 01) and confirm the dashboard looks healthy.
2. Open FO4 Mod Journey Hub (Page 04) and create or select your current project.
3. Run FO4 Setup Wizards (Page 08) to get your environment into a usable state.
4. Open FO4 System & Diagnostics Hub (Page 21) to verify tools, local capabilities, and diagnostics.
5. Ask one small, specific question in AI Chat (Page 02).
6. Use FO4 Knowledge Hub (Page 06) when you need quick reference or searchable learning.
7. Use the specialized hub that matches your task instead of bouncing randomly between pages.
8. Use FO4 Packaging & Release (Page 11) only after your work is tested and ready to ship.

## Common UI Patterns (What You Will See Often)

- Tabs switch between related workflows inside a single platform.
- Status badges show whether a step is healthy, needs attention, or should be stopped.
- Verify, Scan, Refresh, or Re-check buttons update live status after you change something.
- Export, Save, Pin, or Copy buttons help you keep work and references reusable.
- Logs and result panels usually tell you what failed first, what is only a warning, and what to do next.

## If Something Feels Broken

1. Open FO4 System & Diagnostics Hub (Page 21) and run the relevant checks.
2. Open FO4 Runtime Hub (Page 18) if a desktop connection or live link is not behaving.
3. Open FO4 Plugin & Load Order Hub (Page 20) for plugin-order and xEdit-related problems.
4. Open FO4 Packaging & Release (Page 11) if the problem only appears at shipping time.
5. Ask AI Chat (Page 02) with the exact error, tool name, and what you already tried.

## Where to Go Based on Your Goal

- I want to plan a mod: FO4 Mod Journey Hub (Page 04)
- I want setup help: FO4 Setup Wizards (Page 08)
- I need reference or searchable learning: FO4 Knowledge Hub (Page 06)
- I need Creation Kit help: FO4 Creation Kit Hub (Page 09)
- I need texture work: FO4 Textures & Materials (Page 10)
- I need build tooling: FO4 Mod Builder Hub (Page 14)
- I need asset review: FO4 Asset Analysis Hub (Page 15)
- I need automation pipelines: FO4 Automation Orchestrator (Page 16) or FO4 Automation Runner (Page 17)
- I need runtime or tool connectivity help: FO4 Runtime Hub (Page 18)
- I need plugin, xEdit, or load order help: FO4 Plugin & Load Order Hub (Page 20)

## Page 22 - Settings

![Page 22 - Settings](visual-guide-images/page-49-settings.png)

**What this page is for**
Settings is where you configure everything that affects how Mossy behaves across all 22 platforms. It is organized as a nine-step accordion flow so you always know what to configure and in what order. Changes made here — especially tool paths and AI engine settings — affect every other hub in the app.

**How to use it**
1. Work through the steps in order on first use: Privacy → Language → AI Engine → External Tools → Backup.
2. Open Step 4 (External Tools) and run Auto-Detect All to find your installed FO4 tools automatically.
3. Click Browse or enter a path manually for any tool that was not detected.
4. Click Test Launch to confirm each critical tool (xEdit, Creation Kit, F4SE) opens correctly.
5. Save settings after verifying paths — Mossy validates all paths before committing.
6. Export a backup snapshot in Step 5 immediately after a clean setup.
7. Use Step 7 (Internet Access Test) to confirm Mossy can reach online knowledge sources.

**What you will find here**
- Step 1: Privacy & Security — analytics opt-out, data-sharing toggles, and security defaults
- Step 2: Language — UI language selection and translation contribution link
- Step 3: AI Engine — Groq model selector (Llama 3.1 8B, Llama 3.3 70B, DeepSeek R1, Gemma 2, Mixtral), max response tokens (512–4096), self-critique loop toggle
- Step 3b: Local LLM — Ollama endpoint configuration for fully offline AI assistance
- Step 4: External Tools — browse/test-launch paths for xEdit (FO4Edit), Creation Kit, Fallout 4 game root, Papyrus compiler, F4SE, Archive2, LOOT, Mod Organizer 2, Wrye Bash, NifSkope, Blender, BodySlide, Upscayl, GIMP, and more
- Step 5: Backup & Restore — export or import a full settings snapshot as JSON
- Step 6: Tutorial & Onboarding — reset and replay first-run guided experience
- Step 7: Internet Access Test — live connectivity check for Fallout Wiki, Fandom, DuckDuckGo, and Wikipedia with per-provider latency
- Credits & Acknowledgments — searchable open-source library and license list
- Version Info — always-visible app version, build date, and update status

**Helpful tips**
- Set the Fallout 4 root path to the folder containing Fallout4.exe, not the Data subfolder.
- Use llama-3.3-70b-versatile for complex Papyrus scripting help; switch to llama-3.1-8b-instant for real-time voice and quick lookups.
- The xEdit path must point to FO4Edit.exe specifically, not a Skyrim or other game version.
- Run the Internet Access Test whenever AI web-search results feel empty or outdated.
- If a workflow in another hub suddenly stops working, check Settings first — a changed or missing path is often the cause.
