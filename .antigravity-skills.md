# Google Antigravity Skills & Patterns for Mossy

> **Last Updated:** March 2026  
> **Project:** Mossy v5.4.24 (Fallout 4 Modding Assistant)

This guide teaches Antigravity agents how to work effectively within the Mossy codebase while maintaining code quality and security standards.

## 📋 Quick Rules

### ✅ You Can Do These

- Generate React components (`.tsx` files in `src/renderer/src/`)
- Write Vitest unit tests
- Create Playwright E2E tests
- Write Markdown documentation & guides
- Generate TypeScript utilities and services (non-IPC)
- Write build/automation scripts
- Extend `src/shared/types.ts` with new interfaces
- Refactor existing components

### ❌ You CANNOT Do These

- Modify Electron main process (`src/electron/main.ts`)
- Touch IPC handlers or integrations
- Create or modify encryption/security code
- Access environment variables or secrets
- Modify `.env*` files
- Change package.json or build configs
- Write code that touches file system directly

## 🏗️ Component Structure & Patterns

### React Component Template

**Location:** `src/renderer/src/YourComponent.tsx`

```typescript
import React, { useState, useEffect } from 'react';
import { ComponentProps } from '../types'; // Import from existing types

/**
 * YourComponent - Brief description
 * 
 * @example
 * ```tsx
 * <YourComponent 
 *   title="Example" 
 *   onAction={() => console.log('Action')}
 * />
 * ```
 */
export interface YourComponentProps {
  title: string;
  onAction: (data: any) => void;
  isLoading?: boolean;
}

export const YourComponent: React.FC<YourComponentProps> = ({
  title,
  onAction,
  isLoading = false
}) => {
  const [state, setState] = useState<string>('');

  return (
    <div className="p-4 rounded-lg border border-gray-700 bg-gray-900">
      <h2 className="text-xl font-bold text-green-400 mb-4">{title}</h2>
      
      {isLoading && <div className="text-gray-400">Loading...</div>}
      
      <button
        onClick={() => onAction(state)}
        className="px-4 py-2 bg-green-600 hover:bg-green-700 text-white rounded"
      >
        Submit
      </button>
    </div>
  );
};

export default YourComponent;
```

### Key Conventions

| Aspect | Pattern | Example |
|--------|---------|---------|
| **File naming** | PascalCase for components | `ModBrowser.tsx`, `AIAssistant.tsx` |
| **Props interface** | `{ComponentName}Props` | `export interface ModBrowserProps` |
| **Export** | Named export + default export | `export const ModBrowser; export default ModBrowser;` |
| **Styling** | TailwindCSS only (no CSS modules) | `className="p-4 bg-gray-900 text-green-400"` |
| **Comments** | JSDoc with @example tag | `/** ... @example */` |
| **State** | `useState` hooks | `const [value, setValue] = useState('')` |
| **Effects** | `useEffect` with dependency arrays | `useEffect(() => {...}, [dep1, dep2])` |

## 🧪 Testing Patterns

### Vitest Unit Test Template

**Location:** `src/renderer/src/__tests__/YourComponent.test.ts`

```typescript
import { describe, it, expect, vi } from 'vitest';
import { calculateModSize } from '../utils/modCalculator';

describe('modCalculator utilities', () => {
  it('should calculate mod size correctly', () => {
    const result = calculateModSize({
      files: 150,
      totalBytes: 524288000 // 500MB
    });
    
    expect(result).toBe('500 MB');
  });

  it('should handle zero bytes', () => {
    const result = calculateModSize({ files: 0, totalBytes: 0 });
    expect(result).toBe('0 B');
  });

  it('should throw on invalid input', () => {
    expect(() => {
      calculateModSize(null as any);
    }).toThrow();
  });
});
```

### Playwright E2E Test Template

**Location:** `e2e/scenarios/YourFeature.spec.ts`

```typescript
import { test, expect } from '@playwright/test';

test.describe('Mod Browser Feature', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('http://localhost:5174');
    // Wait for app to load
    await page.waitForSelector('[data-testid="mod-browser"]');
  });

  test('should load and display mods', async ({ page }) => {
    const modList = await page.locator('[data-testid="mod-list"] li');
    const count = await modList.count();
    
    expect(count).toBeGreaterThan(0);
  });

  test('should filter mods by search term', async ({ page }) => {
    const searchInput = page.locator('[data-testid="mod-search"]');
    await searchInput.fill('graphic');
    
    await page.waitForTimeout(300); // Debounce
    
    const results = await page.locator('[data-testid="mod-item"]');
    expect(await results.count()).toBeGreaterThan(0);
  });
});
```

### Key Testing Rules

- Mock all IPC calls: `vi.mock('electron', () => ({ ... }))`
- Use `data-testid` attributes in components for E2E targeting
- Test happy path + error cases + edge cases
- Keep tests fast (< 100ms per unit test)
- Use descriptive test names

## 📡 IPC Communication (Renderer Only)

**IMPORTANT:** You can **use** IPC in renderer components, but **cannot modify** IPC handlers.

### How to Use IPC in React Components

```typescript
import { useEffect, useState } from 'react';

export const ToolMonitor: React.FC = () => {
  const [tools, setTools] = useState<Tool[]>([]);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    // Call IPC handler from main process
    window.electron.api.getDetectedPrograms()
      .then((programs) => {
        setTools(programs);
        setIsLoading(false);
      })
      .catch((error) => {
        console.error('Failed to load tools:', error);
        setIsLoading(false);
      });
  }, []);

  return (
    <div>
      {isLoading ? (
        <p>Loading tools...</p>
      ) : (
        <ul>
          {tools.map((tool) => (
            <li key={tool.name}>{tool.name}</li>
          ))}
        </ul>
      )}
    </div>
  );
};
```

### Available IPC Methods

Ask the lead agent for current list of IPC methods. They're documented in:
- `src/electron/main.ts` (handler definitions)
- `src/electron/preload.ts` (exposed API)
- Check `window.electron.api.*` for available calls

## 🚀 Scripts & Automation

### Node Script Template

**Location:** `scripts/your-task.mjs`

```typescript
import fs from 'fs';
import path from 'path';
import { fileURLToPath } from 'url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
const rootDir = path.join(__dirname, '..');

async function main() {
  console.log('Starting task...');
  
  try {
    // Your logic here
    const files = fs.readdirSync(rootDir);
    console.log(`Found ${files.length} files`);
    
    console.log('✅ Task completed');
  } catch (error) {
    console.error('❌ Task failed:', error);
    process.exit(1);
  }
}

main();
```

### Rules
- Use ES modules (`.mjs` extension)
- Print status messages
- Exit with code 1 on error
- Keep scripts focused on one task
- Add to `package.json` scripts if general-use

## ⚠️ Common Mistakes to Avoid

| Mistake | Wrong | Right |
|---------|-------|-------|
| Using CSS modules | `className={styles.container}` | `className="p-4 bg-gray-900"` |
| Hardcoded colors | `style={{color: '#00FF00'}}` | `className="text-green-400"` |
| Missing error handling | `const data = await api.call()` | `try { ... } catch (error) {}` |
| Not typed props | `const Component = (props)` | `const Component: React.FC<Props>` |
| Direct DOM access | `document.getElementById()` | Use React refs or state |
| Secrets in code | `const key = 'sk-1234'` | Load from `window.electron.api` |
| Circular imports | `import from '../../../component'` | Use shared types file |
| Ignoring nulls | `item.name.length` | `item?.name?.length` |

## 📋 Pre-Task Checklist

Before starting a task, verify:

- [ ] All files are in **allowed paths** (check `.antigravity.config.json`)
- [ ] No modifications to Electron, main, backends, or `.env*` files
- [ ] Following existing **naming conventions** from this guide
- [ ] Using **TailwindCSS** for all styling
- [ ] **TypeScript** strict mode (export interfaces for props)
- [ ] **JSDoc comments** for exported functions/components
- [ ] **Tests included** (Vitest for units, Playwright for E2E)
- [ ] **Error handling** included (try/catch, fallbacks)
- [ ] No **hardcoded secrets** or API keys
- [ ] Matches **existing code style** in the repository
